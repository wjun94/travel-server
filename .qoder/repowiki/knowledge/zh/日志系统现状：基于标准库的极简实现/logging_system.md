## 1. 系统/方法概述
该仓库目前**未引入专用的日志框架**（如 Zap, Logrus 等），而是完全依赖 Go 标准库 `log` 包进行日志输出。日志主要用于服务启动、数据库连接初始化以及 WebSocket 异常捕获等关键路径。

## 2. 核心文件与位置
- **入口文件**: `cmd/main.go`
  - 使用 `log.Println` 输出服务启动端口信息。
  - 通过 `gin.Default()` 启用 Gin 框架默认的请求日志（输出到 stdout）。
- **基础设施层**: `pkg/database/mysql.go`, `pkg/database/redis.go`
  - 在数据库和 Redis 初始化阶段，使用 `log.Printf` 记录重试过程，使用 `log.Fatalf` 记录致命错误并终止程序。
- **业务逻辑层**: `internal/handler/common.go`
  - 在 WebSocket 升级失败时使用 `log.Println` 记录简单错误信息。

## 3. 架构与约定
- **无结构化日志**: 当前日志均为纯文本格式，不包含时间戳（除非 `log` 默认配置）、日志级别、TraceID 或业务上下文字段。
- **硬编码输出**: 日志直接输出到标准输出流，未配置日志轮转、文件存储或远程日志收集。
- **缺乏分级策略**: 除了 `Fatalf` 用于不可恢复错误外，其余均使用 `Println/Printf`，未区分 Info, Warn, Error 等级别。
- **Gin 默认日志**: 依赖 `gin.Default()` 提供的中间件记录 HTTP 请求日志，无法自定义格式或过滤敏感信息。

## 4. 开发者建议
- **现状约束**: 目前仅适合开发环境或小型部署。在生产环境中，缺乏结构化日志将导致故障排查困难。
- **改进方向**: 
  - 建议引入 `zap` 或 `logrus` 等高性能结构化日志库。
  - 统一日志初始化逻辑，支持根据 `ENV` 环境变量切换日志级别（如生产环境设为 Info/Error，开发环境设为 Debug）。
  - 为关键业务操作（如支付、AI 生成）添加包含 UserID, TripID 等上下文的日志字段。
